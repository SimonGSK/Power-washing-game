# Power Wash Co.

A single-file browser game: `index.html` is what GitHub Pages serves, and it is **generated** — never edit it by hand. The source lives in `src/` and is assembled by `tools/build.py`.

## Layout

- `src/head.html`, `body.html` — document shell and markup.
- `src/tokens.css`, `bundle.css`, `game.css` — design tokens, `pw-*` components, game-specific styles.
- `src/core.js` — state, save/load, all balance tables (`GEAR`, `SHOP`, `PERKS`, `CHEMS`, `GRIME_TYPES`, `REGIONS`) and formulas.
- `src/sprites.js` + `src/sprites.json` — the sprite engine and the character sprites (text grids). Draw or edit sprites in `tools/pixel-editor.html` (open it over http, e.g. `python3 -m http.server`, so it can load `src/sprites.json`), download, replace the JSON.
- `src/art.js`, `props.js`, `scenes.js` — icons, the truck, scene props and each job's scene. The theme follows the clock by default (`themePref` "auto": night 19:00–06:00; Settings can pin day/night) and a running job keeps the scene it was painted with. Night mode is painted, not overlaid: `R()`/`FX()`/the grime painter/sprites pass every colour through `shade()` (see `NIGHT` in `props.js`); anything drawn inside `lit(fn)` keeps its colour (lamps, windows, glows via `glowCone`/`glowDisc`). New props with a light source should follow `porchLight`/`streetLamp`. `src/icons.json` is generated by `python3 tools/icons_game.py` from the grids in `tools/icons_base.py`, `icons_extra.py`, `icons_game.py`.
- `src/engine.js` — grime, spraying, crew, the job loop. `src/ui.js` + `story.js` — screens, modals, calendar, bills, dialogue, and the `window.PowerWashDebug` test hook at the end.
- `tools/sim.js` — balance simulator (`node tools/sim.js share=0.65 …`).

## Build and test — always before a PR

```bash
python3 tools/build.py     # src/ → index.html (also runs node --check)
npm test                   # builds, then runs the Playwright suite in tests/
```

`npm install` once (and `npx playwright install chromium`) to get the test runner. CI (`.github/workflows/test.yml`) runs the same on every PR and fails if `index.html` is out of date with `src/`, so commit the rebuilt `index.html` together with the source change.

When adding a feature, add or extend a test in `tests/` that would have caught it breaking: the content tests in `tests/content.spec.js` cover the data tables, `job.spec.js` the wash-and-pay loop, `economy.spec.js` bills and upgrades, `helpers.spec.js` the son, foam cannon, tips, overtime, contracts and crew pay (measured by running the helpers alone via `PowerWashDebug.helpersFor`), `sprites.spec.js` the sprite grids, `soak.spec.js` a 45-job career through the real buttons (catches stuck screens and calendar bugs). `content.spec.js` also audits every level for props hidden under the dirt (`PowerWashDebug.auditJob`): props that stand on a washable surface go in the job's `props()` (drawn above the dirt; their footprint is kept clean automatically), never in the scene after `paintArea`. Drive the game through `window.PowerWashDebug` (see the bottom of `src/ui.js`) rather than through private closure state.

## Git workflow — do this without asking

- Never work directly on `main`. At the start of a task, create a branch from `main` named for the task (e.g. `harbor-night-scenes`, `fix-tank-refill`).
- Commit as you go: after each self-contained change that builds and passes `npm test`, commit with a clear message (what changed and why).
- When the task is done and verified in the browser, push the branch and open a ready-for-review pull request with `gh pr create` (title = summary, body = what changed, why, anything to check). Do not open drafts.
- Merge the PR yourself once it's open (`gh pr merge --merge --delete-branch`), then pull `main`. Report the PR URL when done. If a PR already exists for the branch, push to it instead of opening another.
- Don't force-push or rewrite `main`.

## Design system

The look is the "Power Wash Co. Pixel Design System" (a Claude Design System artifact). Its rules are baked into the CSS: tokens as CSS custom properties, `pw-*` component classes, a 3px pixel unit, no border-radius/blur/opacity, pixel icons instead of emoji, scenes painted at 240×150 and shown at 4×. Keep new UI and art inside those rules. Every skill-tree node, shop item and chemical gets its own icon; a chemical's colour is the mid shade of the dirt it removes, and each chemical cuts exactly one dirt type (the rest is plain water). Every job's dirt is capped at a driveway's worth of cells and hp (`REF_CELLS` in `engine.js`), whatever the size of the surface.
